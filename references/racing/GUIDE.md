# レーシングの作り方の参考

## 今回作るもの

参加者が考えたマシン、コース、レースの遊び方で、新しいレーシングゲームを作ります。「しまいろカート」は見栄え・走行操作・競り合いの参考例です。海のコース、2周、相手3台、同じアイテムを全員に指定するものではありません。

便利なコードや素材は再利用できます。参加者の希望に合わせてコース、アイテム、ルール、見た目を変更・追加できます。既存ゲームの絵だけを入れ替えることを制作の範囲にしません。

## 資料

- [SOURCE.md](SOURCE.md)：設定、走行、レース、描画、入力、音をまとめた参考コード。設定値も入っています。
- [settings.sample.json](settings.sample.json)：見本の設定例。変更可能な項目や数値の上限を参加者に課すものではありません。
- [racing.html](../../templates/racing.html)：画像とThree.jsを含み、そのまま遊べる見本。

## 見本から参考にできる仕組み

- `main.mjs`：シーン、HUD、追従カメラと操作をつなぎ、毎フレームの経過時間でレースを更新。
- `driving.mjs` の `driveVehicle`：自分と相手が共通の走行計算を使います。道路の曲率とマシンの向きを別に扱い、アクセルだけで自動的にカーブを曲がらないようにしています。
- 見本の操作は左右でハンドル、Spaceでアクセル、離すとブレーキ、Zでアイテム。ハンドルを切ると少し減速し、戻すと通常の加速へ戻ります。
- `barrier.mjs`：ガードレールとの接触と減速。壁へ押し付ける走行が有利にならず、内側への操作で立て直せます。
- `core.mjs`：順位、周回、勝敗、アイテム取得・使用。全車同じ性能を使い、相手の違いは運転判断で付けています。
- `track.mjs` / `world.mjs`：コースと風景。`models.mjs`、アイテム・ガードレールの描画ファイルは、立体・影・接触演出の参考。
- `input.mjs` / `audio.mjs`：入力のリセットと操作後の音の開始。

この一覧は全機能を保持する義務ではありません。新しいコースや仕組みを作る場合は、設定変更だけに限定せず、計算・描画・操作を合わせて変えられます。見本の検証関数の制約は、新しいゲームの許される範囲ではありません。

## 品質の確認

- ハンドル操作が必要で、曲がる・立て直す判断が結果に結び付く。
- 自分だけが速すぎて独走したり、相手が絶対に勝てない速さだったりしない。
- コースの端やカーブが見やすく、接触時に何が起きたかがわかる。
- アイテムを採用する場合は、効果や使うタイミングがわかり、競り合いに意味がある。
- マシンと背景が希望に合い、走行の見た目・速度感が成立する。
- スタート、順位や進み具合、ゴール、再挑戦が実際に動く。

## 制作の進め方

マシンの希望を聞いて絵を作り、次にコースやレースの希望を一つ聞きます。全部の設定やタイトルが決まるまで待たず、短い希望から遊べるCanvasを作ります。未指定部分は見本をヒントに補えますが、見本と同内容に固定せず、後から自由に変えられるようにします。

生成したマシン画像は、サイズ・向き・カメラと合わせてゲーム内へ反映します。見本の `driverImage` は乗る人の画像用です。マシン全体の絵をその欄へ入れるだけで完了としないでください。

素材・ライブラリーの読み込みを確かめ、実際に遊べる画面と短い操作案内を出します。資料が読めない場合は読めたと言わず、子どもにコード調査や繰り返しの作業を求めず先生へ相談する案内をします。資料の個別ダウンロードやローカルビルドは通常の参加者手順に含めません。できた後は本人が遊び、本人の希望で直します。
